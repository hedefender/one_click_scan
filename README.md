# One Click Scan

One-click document capture, local OCR, PDF and e-mail delivery. Privacy first,
fully local. Android first, iOS later.

Output layout: inside the folder you choose, `pictures/` holds the original
JPEGs and `pdf/` holds the PDFs, with matching names (`YYYY-MM-DD_HH-MM-SS`;
since Phase 3 the PDF of a scan is `pdf/<stem>.pdf`, one file for one or many
pages). The PDF is the picture of each page with an invisible text layer
(search and select) added as a best effort: the app does not promise that the
text is exact. The mail has the subject `One Click Scan - <stem>` (one rule in the
mail app can forward every scan), a one-line neutral body and the PDF; the OCR
text is never in it. Scan produces no JSON; the Budget app reads the PDFs directly.
The app theme always follows the device theme.

Status: Phase 4.1 (the share route opens the provider's own e-mail app, diagnostic line,
one-tap backup way, app password guide) on Phase 4 (mail: SMTP with an app password,
the Send button, the share route as the way out, the OAuth plan) after Phase 3 (PDF in the app: picture + best-effort
text layer, `./pdf`, open button), after Phase 2.1 (spike: searchable PDF, `spikes/pdf_spike/`) and Phase 2 (OCR inside the app: Paddle PP-OCRv5 behind `OcrEngine`, upright working copy, language packs, OCR check screen; the OCR spikes of Phase 1.5 to 1.6c stay in `spikes/ocr_spike/` as the reference). ## Setup (new clone)

This seed contains `lib/`, `test/`, `integration_test/`, `docs/`, and the
Android file that cannot be generated (`android_overlay/`). The platform
folders are generated by `flutter create`; see `docs/CLAUDE_CODE_PHASE_0.md`.

```
flutter pub get
tool/fetch_ocr_models.sh      # OCR models (about 28 MB, not in git), verified by SHA-256
flutter analyze
flutter test
```

Without the models the build and `flutter test` fail with a message that names
the missing file (`verifyOcrModels` in `android/app/build.gradle.kts`,
`test/services/ocr/ocr_assets_test.dart`).
